# Daily research — 2026-11-12

**Headline:** No API changes break the bot today and research was thin, so there are two ideas: drop movers whose volume came from one burst, and show in /week how the trades you took against the scanner's own warnings did.

Focus today: scanner and signal quality, plus the usual API checks.

## Ideas

### 1. Steady-volume check on each mover
- **Area:** scanner · **Effort:** small
- **Why:** A coin can pass the 24h volume floor from one burst and be thin the rest of the day. Count how many of the last 96 15m candles cleared a set dollar volume and flag 'Patchy' below about 80%. Fewer jumpy coins to chase, using candles the scanner already pulls.
- **Notes:** The AnomIQ guide uses a "liquidity score": the share of the last 1,440 one-minute windows whose notional volume cleared $50,000, with a gate of above 80. It also says to set the liquidity floor first, before tuning any spike or flow thresholds. scanner.py today only filters on `quoteVolume >= min_vol_m * 1e6` from /fapi/v1/ticker/24hr, which a single spike can satisfy. The 15m klines are already fetched for EMA 9/21. Field 7 of each kline is quote volume, so this needs no new API calls. The per-candle threshold should scale with `min_vol_m` (for example `min_vol_m * 1e6 / 96 * 0.3`) rather than a fixed $50k. The 15m candles also give a cruder view than 1m windows. Add "Patchy" to the `bad` set so it lowers the score the same way "Late" does, and mirror it in webapp/index.html.

### 2. Warnings you traded through, in /week
- **Area:** discipline · **Effort:** medium
- **Why:** Save the scanner's flags (Crowded, Stretched, OI falling, vs BTC, Late) for each coin when you open a trade. /week then shows trades taken on flagged coins vs clean ones, with P&L. If flagged trades lose, you see it in your own numbers, not as a rule.
- **Notes:** TradeZero's scanner guide recommends reviewing your filter setup every week. This applies that review to your own trades. It's different from the 3 Nov evening scorecard, which grades the morning list against how the coins moved. This one grades your entries against the warnings that were showing when you took them. Two ways to build it: (a) store each /scan result per symbol with a timestamp in store.py, then match trades to the nearest scan within about 30 minutes; or (b) re-score the coin at the trade's open time from historical klines, OI and funding, as backtest.py may already do. Option (a) is simpler but misses coins you never scanned. Label those "not scanned", which also shows trades taken off-list. Revenge trades tend to land on stretched or crowded coins, so cross this with tilt.py's revenge tags.

## Extra notes
- Considered and dropped: an OI × price label ("new longs / short covering / long liquidation / new shorts"), from Sharpe's table. scanner.py already flags "OI falling" when price moves with falling OI, which is the short-covering case, so the label would add little.
- Sharpe's numbers ("record-high OI precedes 10–20% pullbacks", funding above +30% APR means crowded) are the author's own rules of thumb with no sources, so they aren't used here.
- The AnomIQ page is a vendor's product guide. Its thresholds (5m buy-volume z-score above 2.5, OI change above 0.5% over 60m) come from its own event study, so treat them as starting points, not proven numbers.
